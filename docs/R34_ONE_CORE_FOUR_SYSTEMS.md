| 화면·앵커 | 주된 감정 | 한 문장 목표 | 보여줄 것 | 피할 것 | 다음 행동 |

| `invitation` | 안심·행동 | "한 가지 상황부터 함께 볼 수 있다" | 서비스 범위 / 문의 경로 / 필요한 질문 | 가짜 접수 완료, 강제 스크롤 | 실동작 문의 |

### 메인 구조와 깊이의 분리

홈: 시각 → 한 문장 → 짧은 비교 → 실무 연결 → 경로 선택 → CTA.

상세: 선택해서 들어온 사용자가 필요에 따라 연구 원문·작업 구조·근거를 읽도록 설계합니다. 서비스 상세는 구체적 범위, LAB은 반례와 연구, NOTES는 날짜·출처, Studio는 실제 지원 상태, 협업 상세는 실제 기여를 소유합니다.

## 3. 세 공개 상세의 심리 설계

- **LAB — 관찰이 판단이 되는 과정:** 어떤 정보가 실제 사실인지, 어떤 설명이 가설인지, 반례와 다음 확인 조건을 제시한다. Research의 기존 여섯 동시 관점·Chore to Play 원문을 보존한다.
- **NOTES — 근거와 수정:** 노트 목록 한 편부터 원문 링크. Market Notes의 2026.05.11 NEAR 시나리오를 최신 시장 진단·매매 제안처럼 표시하지 않는다. 새 원문이 승인되기 전에는 빈 카드를 채우지 않는다.
- **Signal Studio — 기대와 한계:** 대표가 설명·실사진 → 사실 확인 → 글·장면 → 영상 렌더 → 승인·파일 내보내기까지 이해하게 한다. Gate 0, 세탁업 질문 1개, 릴스 1채널, Mock 결제, 자동 게시 미구현을 일관되게 명시한다.

## 4. MASHCORE–Weplace의 연결

MASHCORE: 왜 망설이는지, 무엇을 확인해야 하는지 해석·설계. Weplace: 별도 합의된 로컬 현장 정보·사진·홈페이지 등 실행·운영. 현장 반응은 두 조직의 역할을 구분한 상태로 Mashcore의 판단 기준을 수정하는 자료로 연결합니다. 고객 사례·실적은 직접 근거와 공개 허락이 있는 경우만 사용합니다.

## 5. 비공개 LEDGER 경계

실제 원장·계좌·채무·세금·보험·현금흐름은 공개 HTML/JS/JSON/빌드·OG·sitemap에 포함하지 않습니다. 내부 와이어프레임은 **빈 상태**만 표시합니다. 비공개 앱은 실DB·인증·객체 권한·보관·복원 검증 후 별도 작업에서 진행합니다. `noindex`는 접근 통제가 아닙니다.

## 6. 모션과 인터랙션 운영 원칙

- 기존 R3.3의 SplitText 2.2초/0.90초와 선택적 proximity를 **보존하여 비교**. UI 반응·CTA는 즉시.
- 메인에서 상시 반복되는 새로운 타이포 모션을 추가하지 않는다. Research 탭은 사용자의 선택에 즉시 반응.
- Field Before/After는 클릭/키보드/터치 입력으로 선택. 데모는 가상 정보 순서 비교일 뿐 실제 매출 성과가 아님.
- 모바일 사진·제목·서비스 CTA는 첫 화면 근처에서 읽힘. 데스크톱·모바일 기능 차별 없음.
- Field/Invitation/서비스/NOTES는 자연 스크롤. 긴 상세에 global mandatory snap 금지.
- `prefers-reduced-motion`, saveData, JS/미디어 실패, 200% 확대, 가로 화면, 브라우저 뒤로가기에서 탈출 보장.

## 7. 이번 와이어프레임의 실제 범위

`MASHCORE_R34_INTERACTIVE_WIREFRAME.html`은 오프라인으로 열 수 있는 **내부 단일 HTML**입니다. 실제 R3.3 QA 이미지에서 일부 장면을 참조한 크롭을 HTML에 내장했으며, 실제 고객사진/새 공개 승인 자산으로 쓰지 않습니다. PC/모바일 모드, 메인/LAB/NOTES/STUDIO/서비스/현장협업, 내부 전용 LEDGER의 빈 상태, Research 탭, 가상 정보 순서 Before/After를 조작할 수 있습니다.

**완료로 해석하지 않을 것:** 별도 네이티브 라우팅, 검색 색인, 새 CMS·원격 Studio·결제·Ledger 실원장, 실제 고객 사례, 운영 배포, 실기기 검수, 성과/전환 입증.
